# Итерация 16 — первое read-only подключение QUIK

Дата: 14 октября 2026 года. Третий срез этапа 7.

Реализованы TCP-клиент чтения, Lua-защита со списком разрешённых команд, независимые диагностические снимки и CLI для запуска на машине с терминалом. Протокол проверен на локальном имитаторе; Lua-защита выполняется в Lua 5.4 через Lupa. Фактическое подключение к пользовательскому терминалу ещё не выполнялось.

Пользователь уточнил два контура: официальный demo QUIK **13.2 x64** и ПСБ **13.0.2.20 x64 / Lua 5.4**. У ПСБ нет демо-счёта. Lua в официальном demo пока не подтверждена; launcher проверяет её до загрузки bridge. [Практическая инструкция](quik-readonly-check.md).

## Транспорт и границы чтения

Исходный контракт изучен в [quik-python commit 0eae024](https://github.com/Alex-Shur/quik_python/tree/0eae024ea43547ab933c705d0951d37e3533d675): [quik_service.py](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/quik_python/quik_service.py), [qsutils.lua](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/lua/qsutils.lua), [qsfunctions.lua](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/lua/qsfunctions.lua). Используется Lua-часть upstream; Python-обёртка с общими торговыми методами и повторами отправки в новый клиент не импортируется.

ReadOnlyQuik открывает два соединения только с числовым 127.0.0.1: запросы/ответы и callbacks. Фреймы — JSON с переводом строки в CP1251, как в изученном bridge. TCP-фрагментация собирается StreamReader; request id и cmd должны совпасть точно. Эти request id — идентификаторы чтения, не торговые TRANS_ID. На таймаут, отмену coroutine, неверный ответ, потерю любого канала или ошибку журнала оба соединения закрываются. Автоматического retry/reconnect нет.

| Разрешено | Аргумент |
| --- | --- |
| tsRuntimeInfo | Пустой; возвращает protocol=1, read_only, метку профиля, QUIK и Lua. |
| ping | Только Ping. |
| isConnected, getClassesList, getTradeAccounts | Пустой. |
| get_orders, get_trades | Пустой: читается видимая таблица целиком. |
| getFuturesClientHoldings, getFuturesClientLimits | Пустой. |
| getInfoParam | Только VERSION, TRADEDATE, SERVERTIME. |
| getClassSecurities | Один точный код класса. |
| getSecurityInfo | class_code\|sec_code, оба идентификатора проверяются. |

Список и аргументы проверяются и Python-клиентом, и TradingSystemReadOnly.lua до вызова диспетчера upstream. sendTransaction, произвольный Lua, служебные команды, запросы подписок и сообщения терминалу не разрешены. Скрипт использует отдельный профиль config.json, проверяет локальные адреса/разные порты, пропускает финансовые/lifecycle callbacks и отсекает ненужные этому диагностическому срезу OnAllTrade/OnQuote и прочий рыночный поток. Профиль — явная локальная метка, не аутентификация брокера.

По умолчанию запрос ограничен 10 секундами, весь CLI-сеанс — 60. Это отдельные диагностические сроки, не замена торговому таймауту 90 секунд. Один фрейм ограничен 1 MiB, очередь callbacks — 1000 элементов и 4 MiB полезных данных, общий объём захваченных байтов одного соединения — 16 MiB. Превышение закрывает сеанс с причиной; молчаливого вытеснения событий нет. Бюджет исходных байтов не равен размеру JSONL/SQLite: base64 и метаданные увеличивают файлы.

## Журнал обмена

Для каждого CLI-запуска создаётся новый каталог, внутри отдельный DurableJournal wire. Исходящий фрейм сохраняется до write; полученный полный или EOF-оборванный фрейм — до JSON-разбора. Байты представлены base64, сохраняются connection_id, тип записи и UTC-время. Некорректные JSON-ключи, NaN/Infinity/переполнение числа, неверная кодировка, структура и номера ответа отклоняются. При превышении лимита фрейма/общего бюджета сохраняется причина остановки; отброшенный сверхлимитный поток не объявляется полностью записанным.

Это запись ограниченного диагностического сеанса, а не восстановление живого финансового stream. Части незавершённого фрейма при принудительной остановке могут не сохраниться. Здесь не вызывается QuikDurableGateway.feed, не изменяются OMS/ledger, не выдаётся GatewayReconciled. Исторические таблицы и callback-события пока не склеиваются в поток исполнений.

## Снимки и результат

capture_snapshot проверяет связь и торговую дату, получает доступные классы и при явном выборе инструмента его справочник. Затем дважды читает счета, заявки, сделки, фьючерсные позиции и лимиты. Порядок строк не создаёт ложного различия. null/не-массив не заменяется пустым списком; дубли и float-ID заявок/сделок отклоняются, большие целочисленные ID сохраняются. Смена таблиц/даты и callbacks во время чтения помечают наблюдение как неповторяемое.

Даже при совпадении остаётся `reconciled=false`: нет атомарного cutover, подтверждения полноты видимых таблиц, начального inventory или новых лимитов капитала. Выбранный инструмент проверяется по классу/коду и положительному tick/lot, но финансовый множитель и маржинальные требования не выводятся автоматически. Демо не считается копией ПСБ.

CLI `python -m trading_system.quik_probe` сохраняет report.json и wire-журнал. Старый каталог не перезаписывается. Консоль показывает профиль, фактические версии, классы и количества строк, без номеров счетов. Код 0 означает повторяемое наблюдение, 2 — изменения во время чтения, 1 — ошибку. Ни один результат не разрешает торговлю.

## Уточнение диагностики — 15 октября

Первый пользовательский запуск завершился на tsRuntimeInfo с общим сообщением «response identity mismatch or Lua error». В QUIK был выведен исходный JSON запроса. Воспроизведение на закреплённом qsfunctions.lua без нашей обёртки даёт тот же лог и ответ lua_error «Command not implemented in Lua qsfunctions module: tsRuntimeInfo». Это указывает на endpoint без read-only обёртки; конкретная запущенная копия у пользователя ещё не установлена, совместимость терминала пока не подтверждена.

Клиент теперь различает несовпадающий ID, несовпадающую команду и ошибку Lua. Для этого точного отказа handshake выдаётся подсказка о TradingSystemReadOnly.lua и портах. Неизвестные тексты Lua не копируются в краткий отчёт: они могут содержать данные счёта и уже сохранены в локальном журнале. После ошибки соединение по-прежнему закрывается, никаких следующих запросов и автоматического повтора нет.

Добавлены два регрессионных теста, уточнён тест чужого ID: **455 тестов**, strict mypy по **48 файлам**. Инструкция дополнена проверкой входного Lua-скрипта, строки запуска, владельца портов и нового каталога повторной диагностики. Следующий пользовательский шаг — повторить подключение с правильным wrapper.
