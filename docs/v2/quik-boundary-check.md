# Проверка доставки callbacks в ПСБ — только чтение

20 октября 2026 года. Ветка `rewrite/v2-quik-boundary`; требуется Python-код и Lua-wrapper из этой ветки. Ранее подтверждённые финансовые параметры и выбор лимита повторно проверять не нужно. Здесь проверяется новая возможность протокола.

## 1. Обновить wrapper

Получите ветку `rewrite/v2-quik-boundary` в рабочий репозиторий. Если в checkout есть свои незавершённые изменения, сначала сохраните их обычным для вас способом; принудительный сброс не нужен.

В терминале ПСБ остановите `TradingSystemReadOnly.lua`. Замените только этот файл копией из `quik/TradingSystemReadOnly.lua` репозитория, рядом с уже работающим `QuikSharp.lua`. Сохраните существующий `TradingSystemReadOnly.profile.local` со строкой `psb-live` и прежний конфигурационный файл портов. Запустите обновлённый `TradingSystemReadOnly.lua`.

Порты остаются **34130/34131**. Если оба терминала используют эти порты, для проверки оставьте запущенным только нужный bridge ПСБ. Изменять Lua-профиль в исходном коде не требуется.

## 2. Выполнить команду

Из корня `TradingSystem` в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile psb-live --expect-version 13.0.2.20 --callback-fence --output .\data\quik-psb-boundary-01
```

Если каталог уже существует, измените окончание на `-02`. Аргументы счёта, инструмента, `--financial` и `--limits` для этой проверки не нужны. Команда только читает таблицы и контролирует доставку callbacks; создавать заявки для проверки не требуется.

## 3. Посмотреть результат

При неизменных таблицах и отсутствии callbacks внутри окна ожидается:

```text
Repeatable observation: True; reconciled: False
Callback boundary: delivery_verified=True; quiet=True; broker_atomic=False
Boundary report: data\quik-psb-boundary-01\boundary.json
```

| Результат | Значение |
| --- | --- |
| `delivery_verified=True; quiet=True` | Доставка до курсоров подтверждена; разрешённых callbacks между ними не обнаружено. |
| `delivery_verified=True; quiet=False` | Доставка подтверждена, но в окно попали callbacks. Это допустимый диагностический результат, без подтверждения повторяемости. |
| `quiet=True`, но `Repeatable observation: False` | Курсоры совпали, однако обнаружено другое изменение, например таблиц или торговой даты; причина находится в `issues`. |
| `callback fence unavailable` | Python обновлён, а запущенный Lua ещё не предоставляет capability. Проверьте путь скрипта и перезапустите обновлённую копию. |
| Таймаут, пропуск номера, другой экземпляр, ошибка отправки/журнала | Доставка не подтверждена; соединение закрыто. Автоматического повторения и разрешения торговли нет. |

Код завершения 0 означает повторяемое наблюдение, 2 — сохранённое наблюдение с изменениями, 1 — отказ диагностики. В случае отказа `boundary.json` не создаётся: достаточно передать текст ошибки из консоли.

Для разбора успешного или изменившегося наблюдения передайте `boundary.json`. Он содержит курсоры, версии, время и признаки проверки, без таблиц счетов и сумм. Полный `report.json`, wire-журнал и `limit-keys.local.json` для этого шага не нужны.

`broker_atomic=False` и `reconciled=False` ожидаемы при любом успешном исходе: доставка сообщений ещё не означает независимую сверку OMS.

## Без терминала

Проверить тот же сценарий с искусственно задержанным callback можно локальным примером:

```powershell
.\.venv\Scripts\python.exe examples/v2_quik_boundary.py
```

Пример поднимает два локальных TCP-соединения и не подключается к QUIK. Он подтверждает поведение клиента, но не заменяет проверку wrapper в вашем терминале.
