# Финансовые параметры SiZ6 — проверка только чтением

16 октября 2026 года. Ветка `rewrite/v2-quik-parameters`, итерация 17.

Подключение демо QUIK 13.2.0.31 / Lua 5.4 и справочник SPBFUT/SiZ6 уже подтверждены. Новый режим читает денежную стоимость шага и поля ГО инструмента. Он создаёт диагностическое наблюдение, не меняет капитал OMS и не выставляет заявки.

## 1. Обновить Python-код и Lua-обёртку

В PowerShell из корня репозитория:

```powershell
git fetch origin
git switch rewrite/v2-quik-parameters
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2
.\.venv\Scripts\python.exe examples/v2_quik_parameters.py
```

Ожидаются **479 тестов** и три строки нового синтетического примера. Его значения ГО вымышленные.

В демо QUIK остановите `TradingSystemReadOnly.lua`. Скопируйте обновлённый файл в подготовленную ранее папку bridge:

```powershell
Copy-Item .\quik\TradingSystemReadOnly.lua .\data\quik-demo-bridge\TradingSystemReadOnly.lua
```

Если вы использовали другую папку, подставьте её фактический путь. Затем снова запустите **TradingSystemReadOnly.lua** в демо QUIK. Используются прежний config.json и закреплённая Lua-часть upstream. Для вашей первоначальной конфигурации остаются профиль demo-quik и порты 34130/34131; если вы меняли порты, передайте свою пару в следующей команде.

Новая обёртка объявляет capability `instrument_parameters_v1`. Без неё `--financial` останавливается с предложением обновить и перезапустить Lua до чтения параметров. Обычная диагностика без этого флага работает и со старой обёрткой.

## 2. Получить параметры

Терминал должен быть подключён к демо-серверу. Выполните:

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2.0.31 --class-code SPBFUT --symbol SiZ6 --financial --output .\data\quik-demo-financial-01
```

Для каждого повтора выбирайте новый каталог. Клиент дважды читает справочник SiZ6 и следующие пять параметров getParamEx:

| Параметр | Что проверяется |
| --- | --- |
| SEC_PRICE_STEP | Положительный шаг котировки; совпадение с min_price_step справочника. |
| STEPPRICE | Положительная денежная стоимость шага. |
| CURSTEPPRICE | Строковый код валюты; в этом срезе поддерживаются SUR/RUB с явным приведением к RUB. |
| BUYDEPO | Положительное наблюдаемое поле ГО покупателя по инструменту. |
| SELLDEPO | Положительное наблюдаемое поле ГО продавца по инструменту. |

В каждом из двух проходов также читаются прежние таблицы счетов, заявок, сделок, позиций и лимитов. Изменение параметров, справочника, таблиц, торговой даты или финансовые callbacks во время чтения не позволяет выдать расчётный коэффициент.

## 3. Прочитать результат

Помимо прежних пяти строк, консоль показывает `Financial parameters`, `Price step`, `Margin observations`, при необходимости `Financial issues` и путь к **instrument.json**.

При полном стабильном ответе для SiZ6 ожидается соотношение стоимости шага к шагу котировки, а не автоматическое использование lot_size=1000. Точные значения берутся из вашего терминала; текущие суммы ГО не зашиты в программу.

- Код **0**: наблюдение прошло заданные проверки. `eligible_for_trading=false` и `reconciled=false` сохраняются.
- Код **2**: данные прочитаны, но неполны, не подходят под поддерживаемый контракт или изменились. Причины находятся в financial.issues; неизвестные значения представлены null, не нулём. Расчётный коэффициент отсутствует.
- Код **1**: ошибка протокола, подключения, записи либо отсутствующая capability; смотрите краткое сообщение и report.json, если он сохранён.

**Пришлите instrument.json** из нового каталога. Он содержит параметры инструмента и их диагностику без таблиц счетов, заявок и сделок. Полный report.json и wire-журнал остаются локально для подробного разбора.

Если параметр недоступен, проверьте в Таблице текущих торгов, видны ли у SiZ6 шаг, стоимость шага, валюта и поля ГО. Пустое значение, result=0 или нулевое ГО не заменяются догадкой: ноль сохранён в исходном ответе, но считается недостаточным для расчётного кандидата в этом срезе. Новые запросы выполняются только при явном повторном запуске.

Поля BUYDEPO/SELLDEPO не равны автоматически брокерскому требованию по конкретному счёту. Время получения данных не доказывает их свежесть на бирже. Автоматическое создание Route, лимитов капитала и возобновление торговли по этому отчёту отсутствуют.

## 4. Если ГО нулевое или пустое

В пользовательской проверке 16 октября, 21:31 МСК оба поля ГО вернулись как result="1", param_type="2", param_value="0.000000", param_image="". Шаг и стоимость шага равны 1, валюта SUR. Оба прохода совпали, но полный финансовый набор не подтверждён. repeatable_observation=false в текущем формате включает неполноту данных, а не только различия между проходами. [Зафиксированный результат](quik-demo-validation.md).

Для следующего сравнения обновление Python или Lua не требуется:

1. В демо QUIK откройте Таблицу текущих торгов для SPBFUT/SiZ6. Добавьте поля ГО покупателя и ГО продавца (BUYDEPO и SELLDEPO); сохраните их точные названия, если терминал показывает другие подписи.
2. Посмотрите значения в этих двух ячейках после загрузки таблицы. Пустая ячейка и отображаемый ноль — разные наблюдения; запишите, что именно видно.
3. Оставив таблицу открытой, повторите команду ниже. Пришлите новый instrument.json и значения этих двух ячеек либо обрезанный снимок строки инструмента.

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2.0.31 --class-code SPBFUT --symbol SiZ6 --financial --output .\data\quik-demo-financial-02
```

Если в таблице положительные значения, а в новом отчёте остаются нули, нужно исследовать получение/обновление параметров API. Если и таблица пустая или нулевая, положительное ГО на данном подключении пока не подтверждено; это не основание считать торговлю бесплатной. Если нужных полей нет в списке доступных параметров, сообщите об этом вместо подстановки другого поля. Проверка таблицы сама по себе не гарантирует устранение причины.

Заказ параметров и момент их доставки требуют отдельного рассмотрения: в [обсуждении поддержки QUIK](https://forum.quik.ru/forum10/topic5631/) описаны ParamRequest и ожидание обновления OnParam. Этот источник не устанавливает причину нулей именно в нашей проверке. Автоматическая подписка, ожидание рыночного обновления и повторные запросы в текущий срез не добавлены.
