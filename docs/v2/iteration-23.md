# Итерация 23 — разрешение неизвестных исходов заявок QUIK

21 октября 2026 года. Ветка `rewrite/v2-quik-outcomes` от `rewrite/v2-quik-repair`. Этап 7 продолжается; число use-case — 32.

## Результат

Добавлена отдельная операция `ResolveOrders`: она восстанавливает потерянные OMS подтверждения регистрации, отказа, отмены и отказа в отмене из сохранённых сообщений durable-шлюза. Операция проверяет актуальное брокерское наблюдение, все исполнения и итоговые состояния заявок, записывает одно решение в журнал и сохраняет торговую блокировку. Она не завершает полную сверку брокера.

| Исход | Необходимые данные | Результат для OMS |
| --- | --- | --- |
| Регистрация | Сохранённый `GatewayAccepted`, явная связь брокерского номера, согласованная строка заявки | `SUBMITTED` → `ACCEPTED`, резерв сохраняется |
| Отказ регистрации | Сохранённый `GatewayRejected`, отсутствие связи зарегистрированной заявки и исполнений | `REJECTED`, резерв заявки освобождается; отсутствие строки само по себе недостаточно |
| Отмена | Сохранённый `GatewayCancelled` для текущего request ID, конечное количество и все соответствующие fills, согласованная строка заявки | `CANCELLED`, освобождается незаполненный остаток, позиция сохраняется |
| Отказ в отмене | Сохранённый `GatewayCancelRejected` для текущего request ID, подтверждённая регистрация и согласованная активная заявка | `ACCEPTED`/`PARTIALLY_FILLED`, резерв активной заявки сохраняется |

Успешный ответ на транзакцию KILL не считается конечным барьером отмены. Неизвестный результат, отсутствие заявки, старый ответ на другой request ID или внешняя отмена без сохранённого подтверждения не получают искусственного terminal status.

## Явное решение по замене

Для подтверждённой отмены с ожидающей заменой требуется `abandon_replacements=(order_id, ...)`: точный список намерений на замену, от которых оператор отказывается. Если список не соответствует ожидающим заменам, вся операция отклоняется, а резерв сохраняется. Команда не создаёт дочернюю заявку.

При отказе в отмене действует прежнее правило OMS: попытка замены не выполняется, исходная заявка остаётся активной. Новый запрос замены — отдельное действие после необходимой сверки и возобновления. Параметр отказа от замены не позволяет скрыто закрывать позиции или отменять другие заявки.

## Источник и граница применения

`QuikDurableGateway.order_evidence` экспортирует `ExecutionEvidence` и сообщения исходов в сохранённом порядке. Они накапливаются из тех же результатов протокола, которые входят в durable-журнал; при открытии старого журнала восстанавливаются детерминированным replay. Схема ранее сохранённых записей шлюза не изменена.

`build_order_resolution` повторно сравнивает полный снимок с OMS. Разрешается изменение только статуса; расхождения количества, цены, стороны, комиссии, маршрута, позиции, внешние записи и неизвестные связи отклоняются. Единственное исключение для отсутствующей/несопоставленной строки — заявка с положительным сохранённым доказательством отказа регистрации. Ранее уже учтённые отказы также проверяются по доказательству и не мешают разрешить следующую заявку.

Все сохранённые исполнения шлюза должны точно совпадать с исполнениями OMS. Если поздний fill отсутствует, сначала применяется [repair исполнений](iteration-22.md), затем строится новая команда исходов с новой revision. Известный барьер отмены, ожидавший эти fills, завершается только после такой проверки. Финансовый учёт здесь не пересоздаётся.

Команда содержит ID операции, revision OMS и шлюза, сессию, digests источника/снимка, срок действия, исходы, целевые параметры/статусы заявок, совокупные позиции и явное решение по заменам. Digests — аудит доверенного процесса, не подпись брокера и не авторизация недоверенного клиента. Срок считается от начала наблюдения; задержка оператора не продлевает свежесть данных.

`apply_order_resolution` вызывается вне обработчиков шины. Он дожидается очереди, захватывает блокировки шлюза и OMS, проверяет здоровые журналы, неизменность источника и точный состав исходов. Публичный `orders.handle(ResolveOrders(...))` отклоняется. Отсутствующий журнал OMS, сбой источника, смена revision или истёкший срок оставляют состояние без изменений.

OMS проверяет исходы на изолированной копии, сверяет все целевые заявки и совокупные позиции, затем записывает одну команду и публикует уведомления. Отказ на второй заявке не оставляет первую применённой. Операция не продвигает планы/дефициты, не создаёт транзакций и требует новой политики капитала. Даже свежая политика капитала не снимает оставшуюся блокировку сверки.

## Повтор и сбои

Точный повтор ID и содержимого — no-op после применения, изменения шлюза, истечения срока и restart. Конфликтующее содержимое с тем же ID отклоняется. Повторная доставка исходов при восстановлении шлюза не возвращает отменённую заявку в активную и не восстанавливает отброшенную замену.

При ошибке записи кандидат не публикуется. Неопределённый результат fsync требует restart. При ошибке уведомления после commit OMS также требует restart; точный повтор в повреждённом процессе не скрывает этот сбой. Долговечность финансового результата не означает exactly-once произвольных внешних эффектов обработчиков стратегии.

## API и пример

```python
await runtime.drain()
view = runtime.orders.observe_gateway(gateway.gateway_id)
command = build_order_resolution(
    operation_id, raw_snapshot, comparison_policy, view, gateway.order_evidence,
    now=clock.now(), current_revision=runtime.orders.revision,
    abandon_replacements=(),  # Только явно выбранные ID отменённых заявок с ожидающей заменой.
)
await gateway.apply_order_resolution(command, runtime.orders)
await runtime.drain()
assert not runtime.orders.ready
```

Офлайн-пример на Windows:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe -m mypy
.\.venv\Scripts\python.exe examples\v2_quik_outcomes.py
```

Пример использует синтетические данные и временные журналы. После исполнения 1 из 4 лотов теряется доставка подтверждения отмены перед заменой. Первая попытка без явного решения сохраняет резерв 450 RUB; явный отказ от замены освобождает остаток заявки, сохраняя позицию 1 лот, её занятость 150 RUB и комиссию 1.25 RUB. Restart и повтор не создают дочернюю заявку. Подключение QUIK не требуется.

## Проверки и оставшаяся область

32 новых теста; всего 724 теста, strict mypy по 62 файлам и 23 офлайн-примера. Проверены исходы регистрации/отмены, поздний fill перед завершением cancel, прежние отказы, request ID, точный отказ от замены, конфликтные payloads, stale/expired команды, атомарность пакета, fsync, уведомление после commit, повтор и restart.

Поддерживаются неизвестные исходы заявок в `SUBMITTED`/`CANCEL_PENDING`. Скрытые ожидающие действия у уже терминальных заявок, затронутые активные планы/защита/аварийное сокращение и истории после inventory cutover требуют отдельного восстановления. Внешние заявки/позиции не импортируются этим API; без стоимости входа, полного покрытия исполнений и явного владения они остаются расхождениями.

Следующий срез — план внешнего учёта с явными данными происхождения, владения и стоимости, связанными с наблюдением и журналом. Реальная приёмка на непустых таблицах, полная граница сверки, источник торгового капитала и контролируемая отправка остаются впереди. Lua-wrapper, профили и порты этого среза не затрагиваются.
