# Проверка фьючерсных лимитов демо QUIK

17 октября 2026 года. Ветка `rewrite/v2-quik-limits`, итерация 18.

Предыдущая проверка финансовых параметров SiZ6 завершена успешно. Теперь проверяем строки таблицы **«Ограничения по клиентским счетам»** и их принадлежность счёту. Это отдельная диагностика чтения; результат не меняет капитал OMS и не включает торговлю.

Для официального демо выберите рабочий день. По [регламенту QUIK Junior](https://arqatech.com/ru/products/quik/basic-sets/quik-broker-training-copy/) учебный срочный рынок по выходным недоступен; запуск его шлюза в рабочие дни указан на 08:55 МСК. Перед повтором убедитесь, что терминал снова показывает SPBFUT и срочный счёт. [Разбор отсутствующего рынка](#5-если-spbfut-и-лимиты-исчезли).

## 1. Обновить Python

Из корня репозитория в PowerShell, после сохранения собственных изменений:

```powershell
git fetch origin
git switch rewrite/v2-quik-limits
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe examples/v2_quik_limits.py
```

Ожидаются **521 тест**. Синтетический пример печатает три строки: раздельные лимиты, точный выбор, отклонение дубликата. Его счета и суммы вымышленные. **Lua обновлять не требуется**: используется уже работающая обёртка после проверки `--financial`. В демо QUIK должен быть запущен `TradingSystemReadOnly.lua` с прежними профилем и портами.

## 2. Получить перечень лимитов

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2.0.31 --class-code SPBFUT --symbol SiZ6 --financial --limits --output .\data\quik-demo-limits-01
```

Для другого настроенного порта добавьте прежние `--request-port` и `--callback-port`. Каталог должен быть новым; следующий запуск, например, сохраняйте в `quik-demo-limits-02`. Команда не повторяет запросы автоматически.

Новый флаг `--limits` анализирует два уже существующих чтения счетов и фьючерсных лимитов. Новых команд Lua нет. `--financial` сохраняет проверку параметров инструмента в том же наблюдении; отдельный запуск только `--limits` тоже поддержан.

При полной стабильной выборке ожидаются `complete=True`, `repeatable=True`. В этом первом запуске **`requested=False; verified=False` нормально**: счёт и строка ещё не выбраны. `reconciled=False` и `eligible for capital: False` остаются всегда. Число строк не фиксировано программой: в прежнем демо-отчёте их было четыре.

| Файл | Назначение |
| --- | --- |
| `limits.json` | Нормализованные поля и причины отказа по обоим проходам; вместо фирмы/счёта — `account-1` и другие условные имена. Суммы сохранены. |
| `limit-keys.local.json` | Локальная расшифровка условных имён и полных ключей для сравнения с терминалом. Содержит реквизиты, не присылайте его. |
| `instrument.json` | Прежний отдельный отчёт инструмента при `--financial`. |
| `report.json`, `wire/` | Полная исходная диагностика; содержит сведения о счетах. Оставьте локально. |

Условные имена действуют только внутри одного запуска; это не постоянные ID счёта. `limits.json` убирает идентификаторы фирмы/счёта и произвольные поля исходных таблиц, но **не скрывает денежные суммы**.

## 3. Сопоставить с терминалом

Откройте в демо QUIK **«Ограничения по клиентским счетам»**. По локальному файлу ключей найдите строки той же фирмы, торгового счёта, типа лимита и валюты. Для строки типа `0` сравните `cbplimit`, `cbplused`, `cbplplanned`, поля под заявки/позиции, обе вариационные маржи и `kgo`. Подробная [карта полей](iteration-18.md#поля-и-единицы) приведена отдельно. Значения могут измениться после момента чтения — это нужно отличать от неверного соответствия полей.

Типы `0`, `3`, `6`, `7` сохраняются отдельными строками. Пустая валюта, нулевые и отрицательные суммы не исправляются подстановками. `SUR` и `RUB` имеют одинаковый нормализованный смысл для поддержанной валютной политики, но остаются **разными ключами строк**. Ничего не складывайте и не выбирайте по наибольшей сумме.

Для обсуждения результата достаточно **`limits.json`** и сообщения, совпадают ли значения с таблицей терминала. При расхождении укажите условное имя счёта, тип, валюту и название поля. Реквизиты счёта не нужны. Если суммами делиться не хотите, пришлите строки состояния из консоли и перечень `issues`.

## 4. Явно выбрать одну строку

После сопоставления можно запустить вторую проверку. Скопируйте точные значения из своего `limit-keys.local.json` в переменные ниже; текстовые заглушки нужно заменить. Для этого среза подтверждается только тип `0` с валютой `SUR` либо `RUB` ровно как в ключе:

```powershell
$limitFirm = 'ЗАМЕНИТЬ_НА_firmid'
$limitAccount = 'ЗАМЕНИТЬ_НА_trdaccid'
$limitCurrency = 'SUR'
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2.0.31 --class-code SPBFUT --symbol SiZ6 --financial --limits --limit-firm $limitFirm --limit-account $limitAccount --limit-type 0 --limit-currency $limitCurrency --output .\data\quik-demo-limits-02
```

Все четыре части ключа обязательны вместе. Программа требует единственную строку с этим ключом в каждом проходе и единственный соответствующий счёт с классом SPBFUT. При дублях, неизвестном счёте, неподдержанном выборе, некорректных полях или изменившемся снимке `verified=False`; запасной счёт не выбирается. Некорректная другая строка тоже блокирует подтверждение всего наблюдения.

Код завершения `0` означает успешную диагностику в запрошенном режиме, `2` — сохранённое, но неподтверждённое наблюдение, `1` — ошибку подключения/чтения/сохранения. Ошибка синтаксиса CLI также возвращает `2`, но до подключения и создания каталога. При неподтверждённом общем снимке финансовый кандидат тоже снимается.

Даже `verified=True` подтверждает лишь точное повторяемое наблюдение. Преобразование брокерских полей в доступный капитал, граница снимков/callbacks и сверка с OMS остаются следующими историями этапа 7.

## 5. Если SPBFUT и лимиты исчезли

При `requested class is not offered by this terminal` запрос справочника SiZ6 и чтение лимитов ещё не выполнялись. Текущий отчёт об этой ошибке не содержит список классов. Для диагностики доступных данных запустите режим без инструмента в новом каталоге:

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2.0.31 --limits --output .\data\quik-demo-limits-02
```

Если этот каталог уже существует, выберите следующий номер. При отсутствии срочного рынка могут остаться QJSIM, один фондовый счёт и пустые futures holdings/limits. Это не подтверждённый нулевой капитал срочного счёта. Отсутствие лимитов даёт `limits.empty`, `complete=False`, `repeatable_observation=False`, даже когда обе выборки полностью совпадают. Само имя repeatable_observation означает прохождение всех проверок, включая полноту; изменение данных определяется отдельными причинами `tables_changed`, `limits_changed`, `accounts_changed`.

Такой результат получен пользователем в субботу **17 октября 2026, 15:34 МСК** и соответствует опубликованному ограничению выходного дня. Проверка транспорта и сохранения неполного наблюдения состоялась; положительная проверка лимитов требует доступного срочного рынка. [Зафиксированный результат](quik-demo-validation.md#отсутствие-срочного-рынка-в-выходной--17-октября-1534-мск).

Следующий повтор для этого случая — в понедельник **19 октября**, после появления срочного рынка, например после 10:00 МСК. Вновь выполните полную команду с `--class-code SPBFUT --symbol SiZ6 --financial --limits`, указав новый каталог `quik-demo-limits-03`. Расписание не гарантирует фактическую доступность сервера; если в рабочее время SPBFUT и срочный счёт не вернутся, сначала проверьте их наличие непосредственно в терминале. Для продолжения разбора достаточно вывода консоли и `limits.json`; файл полных ключей оставьте локально. Обновление Python или Lua для повтора не требуется.
