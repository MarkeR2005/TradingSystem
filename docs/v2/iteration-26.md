# Итерация 26 — сохраняемый результат локальной сверки

22 октября 2026 года. Ветка `rewrite/v2-quik-reconciliation-checkpoint` от `rewrite/v2-quik-inventory-adoption`. Этап 7 продолжается; число use-case остаётся 32.

## Результат и граница среза

После принятия внешнего учёта можно сохранить точный результат сравнения нового наблюдения QUIK с OMS и журналом шлюза. `QuikReconciliationCheckpoint` связывает принятую базу, полные журнальные префиксы, revisions, исходный снимок, политику его интерпретации и срок актуальности. Дальнейшее исполнение требует нового наблюдения и новой контрольной точки.

В предыдущем плане этот шаг включал управляемый торговый допуск. Проверка показала, что нынешний транспорт не связывает наблюдение с durable-потоком и не доказывает брокерскую атомарность/покрытие истории. Поэтому в этой итерации реализован сохраняемый локальный результат; снятие торговой блокировки не реализовано. Это явное ограничение объёма, а не объявление полной сверки завершённой.

Контрольная точка не меняет финансовый учёт, резервы, владельцев позиций, капитал или состояния стратегий. Она записывается только в журнал шлюза. `current=True` означает неизменность проверенных локальных источников в пределах срока; `reconciled`, `eligible_for_trading` и `eligible_for_capital` остаются `False`.

## Что проверяется перед записью

1. Оба журнала доступны, доставка не завершилась неопределённой ошибкой, gateway attached/recovered. Принятое решение внешнего учёта одинаково в OMS и шлюзе. Незавершённый импорт не подходит.
2. Политика покрывает все настроенные маршруты шлюза, включая пока пустые. Совпадают сессия, часовой пояс, шаг цены и контракт комиссий.
3. Исполнения OMS точно совпадают с сохранёнными исполнениями шлюза. Незавершённые исходы, несовпадающие заявки/позиции, неполная наблюдаемая история и неизвестные комиссии отклоняются обычным сравнением. Сохранённый отказ регистрации учитывается только при совпадении состояния OMS и причины отказа.
4. Не остаётся несопоставленных callbacks. Зафиксированные ошибки протокольного входа после принятия базы запрещают новую контрольную точку, даже если следующий снимок выглядит согласованным. Restart не скрывает такие ошибки; отдельный протокол их разрешения пока не реализован.
5. Новое наблюдение начинается не раньше последнего сохранённого входа шлюза. Повторное использование исходного снимка импорта для проверки последующего состояния отклоняется. Это проверка локальной хронологии, а не брокерский watermark.
6. После опустошения очереди под блокировками шлюза и OMS результат строится заново. Смена revision, содержимого любого журнала, снимка, настроек или срока запрещает запись старого предложения.

OMS-журнал также содержит checkpoints стратегий, которые не увеличивают revision OMS. Поэтому сравниваются и число записей, и SHA-256 всего префикса. Хеши фиксируют соответствие локальных данных; подписью брокера они не являются. Исходный read-only снимок сохраняет вызывающий код; в checkpoint записывается его digest, а не ещё одна копия таблиц.

## Когда результат устаревает

| Событие | Поведение |
| --- | --- |
| Новый input шлюза, включая финансово нейтральный дубль | `gateway_changed`; требуется новое наблюдение |
| Изменение OMS или записи состояния стратегии в общем журнале | `oms_changed` |
| Разрыв соединения и последующий `OnConnected` | Старая точка не становится актуальной повторно |
| Истечение срока / откат часов | `expired` / `clock_regressed` |
| Ошибка доставки, деградация или закрытие журнала | Результат не считается актуальным |
| Restart | Контрольная точка доступна как история; запись restart делает её устаревшей |
| Точный повтор сохранённой операции | Нет новой записи и продления срока |
| Тот же ID с другим содержимым | Ошибка конфликта |

`reconciliation_status` вычисляет статус при каждом обращении. Ранее возвращённый объект — неизменяемый результат прежнего чтения; его нельзя хранить как разрешение на будущую операцию.

Даже актуальный результат сохраняет четыре ограничения: `broker_atomicity_unverified`, `history_coverage_unverified`, `position_cost_basis_unverified`, `gateway_cutover_unverified`. Принятая стоимость остатка остаётся декларацией с источником. Транспортный курсор снимка не доказывает, что именно этот поток прошёл durable-шлюз.

## Запись, повтор и восстановление

```python
checkpoint = gateway.reconciliation_checkpoint("check-01", runtime.orders, raw_snapshot, policy)
await gateway.record_reconciliation(checkpoint, runtime.orders, raw_snapshot, policy)
status = gateway.reconciliation_status("check-01", runtime.orders)
assert status.current
assert not status.eligible_for_trading
```

Input/result сохраняются прежним протоколом шлюза. Ошибка до input не создаёт результат; сохранённый input без result завершается при replay. Неопределённый fsync требует restart. Проверяется соответствие checkpoint предшествующей истории шлюза; до финансовой redelivery сверяются также префиксы OMS, на которые ссылаются сохранённые точки.

В журнал записывается время повторной проверки под блокировками. Если реальные часы пересекли срок непосредственно перед append, запись остаётся восстанавливаемой; последующее чтение статуса покажет истечение срока. Граница актуальности не продлевается.
