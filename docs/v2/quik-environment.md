# Среда Windows для этапа QUIK

Обновлено: 14 октября 2026 года. Один репозиторий — `MarkeR2005/TradingSystem`; выделять дополнительные не требуется.

## Что можно запустить сейчас

Итерации 14–15 проверяют протокол и восстановление без терминала. На Windows нужны Python 3.12 и Git. Из корня репозитория, в ветке `rewrite/v2-quik-durability`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe -m mypy
.\.venv\Scripts\python.exe examples/v2_quik_contract.py
.\.venv\Scripts\python.exe examples/v2_quik_recovery.py
```

Ожидается 414 тестов, отсутствие ошибок типов и четыре сообщения примера: обработка раннего/позднего fill, результат 18 RUB, сохранённый резерв 150 RUB после таймаута и заблокированный OMS после restart. Активация PowerShell-окружения не нужна. Новый пример восстановления показывает два перезапуска: 1 лот, комиссия 1.25 RUB, резерв 450 RUB и следующий TRANS_ID 2 без повторной отправки. Эти команды не устанавливают соединение с брокером и не отправляют торговые заявки.

## Подтверждённый контур ПСБ

По сообщению пользователя от 14 октября: брокер ПСБ, актуальная установленная версия QUIK, Lua из комплекта терминала. Номера сборок и фактическая совместимость bridge пока не проверены. Разработка read-only транспорта может продолжаться без подключения. Для живого smoke test понадобятся точный номер сборки QUIK, разрядность, версия Lua (`_VERSION`) и сведения о поставляемом Lua runtime для выбора совместимой DLL. Затем уточняются параметры профиля из таблицы ниже; пароли передавать не требуется.

## Подготовка терминала к следующему срезу

Понадобится Windows-машина с QUIK вашего брокера и доступом к демонстрационному контуру фьючерсов. Если такого контура нет, первый сеанс интеграции ограничивается чтением данных. Зафиксируйте фактическую версию QUIK, разрядность и версию встроенной Lua; сборка DLL должна соответствовать именно им. Точную минимальную версию QUIK этот срез не устанавливает — терминал здесь не запускался.

В качестве исходной точки используем `quik-python`, уже выбранный в прототипе. Для воспроизводимости изучена версия исходников с `pyproject.toml` 1.2.0, commit `0eae024ea43547ab933c705d0951d37e3533d675`. Подготовить копию можно вне каталога проекта:

```powershell
git clone https://github.com/Alex-Shur/quik_python.git quik-python-reference
git -C quik-python-reference checkout 0eae024ea43547ab933c705d0951d37e3533d675
```

Установка Python bridge в рабочее окружение будет добавлена вместе с read-only транспортом и его проверками. Сейчас его не нужно импортировать или вызывать `send_transaction` из тестового адаптера.

По [инструкции автора](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/README.md) Lua-файлы копируются в отдельный доступный QUIK каталог; через диалог Lua-скриптов запускается `QuikSharp.lua`. Подробности выбора DLL находятся в [lua/USAGE.RU.md](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/lua/USAGE.RU.md). Не следует выбирать библиотеку по одному только названию 64-bit: учитываются версия Lua и вариант её сборки. Если требуется runtime Visual C++, используйте ссылку Microsoft из исходной инструкции.

В изученном [config.json](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/lua/config.json) основной профиль использует локальный адрес `127.0.0.1` и порты 34130/34131. Для первого подключения Python и терминал размещаем на одной машине, эти настройки сохраняем. Здесь не требуется открывать порты в интернет или настраивать VPS.

## Данные для профиля подключения

| Что нужно определить | Зачем |
| --- | --- |
| Брокер, версия QUIK/Lua, доступность demo | Воспроизводимая конфигурация терминала и допустимый режим проверки. |
| Реальный ACCOUNT, при необходимости CLIENT_CODE/FIRM_ID | Точное адресование счёта без подстановки ID транзакции вместо кода клиента. |
| Класс SPBFUT и выбранный фьючерс | Проверка instrument metadata, шага цены, целого лота, валюты и множителя. |
| Часовой пояс timestamps терминала | Преобразование времени сделок в UTC без использования времени получения. |
| Состав и момент появления комиссий | Выбор компонентов без повторного суммирования включённых сборов. |
| Действующие внешние заявки и остатки | Начальная полная сверка и manual-учёт. |

Секреты входа в QUIK не требуются коду тестов и не должны храниться в репозитории. ACCOUNT и коды инструментов — параметры будущего профиля, а не значения из синтетического примера `demo/TEST`.

## Готовность к отправке заявок

Сохранение идентификаторов и исходных JSON-событий реализовано в итерации 15. Следующий срез добавляет read-only подключение и независимую сверку; реальная отправка пока отсутствует. До допуска исполнения должны пройти проверка разрыва связи/повторного подключения и сравнение брокерских заявок, сделок и остатков с OMS. После этого отдельно проверяются лимитная заявка, частичное исполнение, отмена/замена и защитный выход на демонстрационном счёте.

Текущие 90 секунд — срок ожидания определённого ответа в контрактном replay. Его истечение означает необходимость сверки; ни отсутствие заявки, ни успешную отмену оно не доказывает. Нативные стопы, живой scheduler, маржинальные требования и реальное исполнение этой итерацией не проверены.

## Рабочие журналы

`QuikDurableGateway` требует отдельного постоянного каталога, например `data/quik`, а OMS — `data/oms`. Пример использует временные каталоги и удаляет их после завершения. В рабочем запуске оба журнала сохраняются между сеансами; нельзя менять session_id, metadata и комиссионную политику для существующего журнала либо удалять его ради снятия блокировки. На restart сделки доставляются повторно с прежними execution_id, а gateway остаётся заблокированным до будущей сверки. [Контракт восстановления](iteration-15.md).
