# Среда Windows для этапа QUIK

Обновлено: 15 октября 2026 года. Один репозиторий — `MarkeR2005/TradingSystem`; выделять дополнительные не требуется.

## Что можно запустить сейчас

Итерации 14–16 проверяют протокол, восстановление и read-only транспорт без реального терминала. На Windows нужны Python 3.12 и Git. Из корня репозитория, в ветке `rewrite/v2-quik-readonly`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe -m mypy
.\.venv\Scripts\python.exe examples/v2_quik_contract.py
.\.venv\Scripts\python.exe examples/v2_quik_recovery.py
.\.venv\Scripts\python.exe examples/v2_quik_readonly.py
```

Ожидаются 455 тестов и успешная проверка типов по 48 файлам. Примеры проверяют callbacks, восстановление и два чтения синтетического TCP-терминала. Они не устанавливают соединение с брокером. Активация PowerShell-окружения не нужна. Lupa 2.6 используется только тестами Lua-защиты; рабочий Python-клиент не имеет сторонних зависимостей.

## Первое подключение

[Пошаговая инструкция](quik-readonly-check.md) описывает отдельную папку Lua bridge, закреплённый upstream commit, запуск **TradingSystemReadOnly.lua** и команду **quik_probe**. Python и QUIK запускаются на одной Windows-машине. Оба сокета ограничены 127.0.0.1, для демо используются порты 34130/34131. Скрипт проверяет Lua 5.4 до загрузки DLL и допускает только перечисленные команды чтения.

Используется Lua-часть `Alex-Shur/quik_python`, commit `0eae024ea43547ab933c705d0951d37e3533d675`. Python-пакет quik-python устанавливать не требуется: наш клиент реализует ограниченный транспорт без автоматического повтора запросов. Сам `QuikSharp.lua` отдельно не запускается — его загружает защитный wrapper.

Секреты входа в QUIK не требуются коду тестов и не должны храниться в репозитории. ACCOUNT и коды инструментов — параметры будущего профиля, а не значения из синтетического примера `demo/TEST`.

## Готовность к отправке заявок

Сохранение идентификаторов и исходных JSON-событий реализовано в итерации 15. Итерация 16 добавляет read-only подключение и два диагностических чтения; они не являются атомарной сверкой и всегда имеют `reconciled=false`. Реальная отправка пока отсутствует. До допуска исполнения должны пройти проверка разрыва связи/повторного подключения и сравнение брокерских заявок, сделок и остатков с OMS. После этого отдельно проверяются лимитная заявка, частичное исполнение, отмена/замена и защитный выход на демонстрационном счёте.

Текущие 90 секунд — срок ожидания определённого ответа в контрактном replay. Его истечение означает необходимость сверки; ни отсутствие заявки, ни успешную отмену оно не доказывает. Нативные стопы, живой scheduler, маржинальные требования и реальное исполнение этой итерацией не проверены.

## Рабочие журналы

`QuikDurableGateway` требует отдельного постоянного каталога, например `data/quik`, а OMS — `data/oms`. Пример использует временные каталоги и удаляет их после завершения. В рабочем запуске оба журнала сохраняются между сеансами; нельзя менять session_id, metadata и комиссионную политику для существующего журнала либо удалять его ради снятия блокировки. На restart сделки доставляются повторно с прежними execution_id, а gateway остаётся заблокированным до будущей сверки. [Контракт восстановления](iteration-15.md).

Диагностика `quik_probe` создаёт новый каталог для каждого запуска: `report.json` и отдельный журнал `wire`. Она не открывает и не изменяет журналы OMS/QuikDurableGateway. Отчёт может содержать данные счёта; для первой обратной связи достаточно пяти строк консоли.
