# Итерация 20 — граница доставки callbacks QUIK

20 октября 2026 года. Ветка `rewrite/v2-quik-boundary` от `rewrite/v2-quik-capital`. Продолжение этапа 7; число use-case остаётся 32.

## Проблема и результат

Ответы на запросы и callbacks приходят по разным TCP-соединениям. Два чтения таблиц могут совпасть, а уже созданный Lua callback ещё находиться в пути. Сравнение только локального количества полученных сообщений не обнаруживает такую задержку.

Добавлен явный режим `--callback-fence`: Python получает курсор Lua до и после двух проходов и ждёт сохранения всех сообщений после начальной границы соединения до указанного номера. Неподтверждённая доставка прерывает диагностику; обнаруженная активность снимает повторяемость наблюдения. Сверка с OMS и разрешение торговли в этот срез не входят.

## Контракт

| Элемент | Правило |
| --- | --- |
| Capability | `callback_cursor_v1` в `tsRuntimeInfo`; старый wrapper продолжает обычную диагностику, но новый режим с ним завершается явным отказом. |
| Курсор | `bridge_session`, `sequence`, `failed_sends`. Сессия относится к экземпляру Lua; это различитель запусков, не средство аутентификации. |
| Начальная граница | Курсор из runtime handshake. История до него и периоды без подключённого наблюдателя не подтверждаются. |
| Порядок | Каждый разрешённый callback увеличивает sequence. Отфильтрованная рыночная лента его не меняет. Разрывы, повторы транспортного номера, регрессия и другой экземпляр Lua отвергаются. |
| Ошибка отправки | Рост `failed_sends` после начальной границы блокирует результат, даже без последующего callback. Счётчики ограничены; переполнение не обнуляется. |
| Подтверждение | Исходный кадр сохраняется в wire-журнале до разбора. Успешная граница также сохраняется до возврата из `callback_fence()`. Очередь прикладных callbacks при этом не очищается. |
| Два соединения | Callback может обогнать ответ с курсором. Это допустимо, если курсор не старее сообщений, полученных ещё до запроса, и предыдущего запрошенного курсора. |
| Неопределённость | Таймаут, разрыв, отмена начатого ожидания, неверные метаданные, ошибка журнала или отправки закрывают соединение без автоматического повторения. |

Lua увеличивает счётчики только в обработчике callbacks; команда `tsCallbackCursor` читает их и отвечает по обычному каналу запросов. Нового писателя в callback-сокет из `main` не добавлено. Lua возвращает отдельную таблицу курсора и не изменяет исходный callback. Python ограничивает и основную очередь, и буфер ранних метаданных до завершения handshake.

`delivery_verified=True` означает доставку до двух запрошенных транспортных курсоров в пределах текущего подключения. `quiet=True` означает равенство этих курсоров. Если callback создан между ними, появляется `bridge_callbacks_during_scan`, даже когда таблицы одинаковы. Существующие проверки таблиц, даты, финансовых параметров и лимитов продолжают действовать.

`broker_atomic=False` и `reconciled=False` сохраняются. Курсор не доказывает полноту серверной истории, момент обновления таблиц относительно callbacks, отсутствие ещё не вызванного callback или непрерывность предыдущего подключения. Даже спокойное окно не является атомарным снимком брокера. Транспортные номера также не заменяют идентификаторы сделок: два сообщения об одной сделке сохраняются для последующей финансовой дедупликации.

## Проверка через TDD

37 новых тестов, всего 611; strict mypy по 56 файлам, 20 примеров. Проверяются Lua 5.4 через Lupa и реальный локальный TCP с независимыми каналами:

- callback, задержавшийся после ответа и после двух одинаковых чтений;
- callback перед ответом, ранние сообщения handshake и ненулевой начальный курсор;
- пропуски, дубли транспортного номера, регрессия, смена экземпляра, неверная схема и рост ошибок отправки;
- таймаут, отмена, разрыв, отказ записи подтверждения, сериализация параллельных запросов;
- отказ старого wrapper до чтения таблиц, отсутствие тихого отката к прежнему режиму;
- отдельный `boundary.json` без таблиц счетов, полных ключей и денежных сумм.

Две дополнительные регрессии различают устаревший курсор относительно уже полученного сообщения и допустимое опережение ответа callback, пришедшим во время самого запроса.

```powershell
.\.venv\Scripts\python.exe examples/v2_quik_boundary.py
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe -m mypy
```

Пример сам запускает loopback-сервер, задерживает callback относительно ответа и показывает: доставка подтверждена, таблицы совпали, но спокойного окна нет. Подключение к терминалу для примера не требуется.
