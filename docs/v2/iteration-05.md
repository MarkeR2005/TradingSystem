# Итерация 5: общая история свечей и одиночный бэктест

Дата: 9 октября 2026 года. Ветка `rewrite/v2-backtest`, база `rewrite/v2-lifecycle`. Срез этапа 4 разрабатывался через XP/TDD: сначала приёмочные тесты для новых контрактов, затем реализация и проверки выявленных границ. Реестр остаётся прежним: 32 use-case.

## Что теперь можно сделать

Автор стратегии запрашивает завершённую историю для прогрева через `context.load_history`, обрабатывает обычные свечи и отдельно реагирует на коррекции. Исследователь запускает свежий экземпляр этой же стратегии через `SingleBacktest` и получает заявки, исполнения, позиции, сделки, закрытую эквити и финансовый результат по последнему доступному close.

Используются обычные `TradingRuntime`, OrderManager и PositionLedger. Второй независимой бухгалтерии для исследований нет. Каждый запуск создаёт собственные часы, шлюз, историю, очереди и идентификаторы. Передача live-шлюза или live-runtime в API запуска не предусмотрена.

## История, маршрутизация и прогрев

`CandleBook` хранит один неизменяемый бар на ключ instrument/timeframe/opened_at. Точный повтор ничего не публикует. Новая версия известного ключа обновляет историю и создаёт `CandleCorrected(previous, candle)`. Runtime вызывает `on_correction(context, previous, corrected)`, сохраняя текущие часы; обычный `on_candle` повторно не вызывается. Финансовые исполнения по прошлому бару не пересчитываются.

Новые бары каждой серии должны идти без перекрытий и в порядке времени. Неизвестный старый бар отклоняется: автоматическая загрузка пропусков пока не реализована. Валидация предшествует изменению часов. Серии инструментов и таймфреймов независимы.

Общая история обновляется и при паузе стратегии. Рыночные callbacks, включая коррекции, доставляются только в `RUNNING` при готовом OMS. Несколько стратегий используют один экземпляр бара/истории. По умолчанию стратегия принимает все таймфреймы своих инструментов; `accepts_candle` позволяет явно фильтровать их. Фильтр выполняется внутри runner: его ошибка переводит конкретную стратегию в `FAILED`, а остальные потребители продолжают работу. Агрегации таймфреймов и объединения upstream-подписок брокера ещё нет.

`context.load_history(HistoryRequest(...))` возвращает проверенный неизменяемый tuple и запрещает `end` позже текущих модельных часов. По умолчанию источник — общий CandleBook; можно по-прежнему инъецировать HistorySource. Прогрев инициирует автор в `on_start`, восстановление индикаторов — в `on_restore`. История прогрева не воспроизводится как торговые callbacks и не создаёт fills. Сам кэш OHLC не записывается в durable journal; после рестарта его нужно наполнить из источника истории.

## Синтетические интервалы

`fill_gaps(instrument, timeframe, expected_openings, candles, seed=...)` получает явный список ожидаемых открытий. Перерывы, отсутствующие в списке, не заполняются. Реальный календарь биржи функция не угадывает.

Пустой интервал получает O=H=L=C, равные предыдущему close, нулевой объём и `synthetic=True`. Если первый интервал пуст, требуется seed; более поздний бар не используется как начальная цена. Некорректные seed, дубликаты, перекрытия и бары вне списка отклоняются. Реальная поздняя свеча может заменить синтетическую через обычную семантику коррекции.

Синтетическая свеча доступна индикаторам и торговой логике, но HistoricalGateway не создаёт по ней исполнений. Это выбранная граница первой модели: заполненная цена не считается свидетельством рыночной ликвидности. Правила live last/mid остаются на этапе источника данных.

## Историческое исполнение

Первый runner ограничен одной стратегией, одним инструментом и одним таймфреймом. Он принимает готовые Candle и явный BacktestConfig, без подключения к брокеру или загрузки внешних данных.

На закрытии каждого бара шлюз сначала создаёт исполнения доступных ранее заявок, runtime полностью обрабатывает order/fill callbacks, затем получает свечу и обрабатывает её сигналы. Заявки из candle/fill callbacks ждут следующего бара. Таймеров в этом срезе нет.

| Условие | Поведение |
| --- | --- |
| Заявка отправлена до или в момент открытия бара | Может исполняться на этом баре |
| Заявка отправлена после открытия, включая сигнал на его закрытии | На этом баре не исполняется |
| Market BUY / SELL | High / Low доступного следующего реального бара — консервативная OHLC-модель |
| Limit BUY | При Low ≤ limit исполняется по limit |
| Limit SELL | При High ≥ limit исполняется по limit |
| Цена не достигнута | Заявка остаётся активной |
| Синтетический бар | Исполнений нет |
| Отмена/замена | Общий протокол OMS: подтверждение отмены, затем новый остаток и новая цена |

Включая гэп в выгодную сторону, лимит исполняется по своей цене. Модель не улучшает цену до open. Объём исполняется полностью; комиссия задаётся в RUB на лот. Объём свечи не ограничивает количество, очередь заявок и внутрибарная последовательность цен не моделируются. Stop/iceberg, частичные исторические fills, частые перестановки, задержки и Монте-Карло впереди. Управляемые partial fills и cancel-races продолжают проверяться прежним SimulationGateway.

## Результат и воспроизводимость

`BacktestResult` содержит конфигурацию, имя стратегии, SHA-256 использованной истории, общее количество баров и число синтетических, tuples заявок/исполнений/позиций/сделок/эквити, цену и время финальной оценки.

| Поле | Значение |
| --- | --- |
| `closed_pnl` | Последняя точка закрытой эквити; меняется после flat всего цикла |
| `realized_pnl` | Реализованные ценовые движения минус все комиссии, включая открытый цикл |
| `unrealized_pnl` | Открытое количество × (последний close − средняя цена) × множитель контракта |
| `total_pnl` | realized_pnl + unrealized_pnl |
| `commission` | Сумма комиссий всех исполнений; уже вычтена из realized_pnl |
| `pending_orders` | Нетерминальные заявки на конце данных |
| `marked_at` / `mark_price` | Время закрытия и close последнего фактически обработанного бара |

Конец истории не вызывает автоматического закрытия или вымышленного fill по последнему close. Начальный капитал/доходность в процентах не рассчитываются: распределение и ограничения счетов относятся к этапу 5. Отчётная валюта пока RUB.

История сортируется и проверяется до запуска; пустой торговый диапазон, дубликаты, перекрытия, чужие инструменты/таймфреймы и бары, пересекающие границы диапазона, отклоняются. История до start используется только для прогрева, после end не подаётся стратегии и не входит в digest. Заявки должны использовать ровно Instrument из конфигурации, включая множитель/шаг/валюту; иначе отчёт не создаётся.

Фабрика обязана вернуть свежий экземпляр стратегии. Повторное использование экземпляра в одном SingleBacktest отклоняется. Для детерминированной стратегии одинаковые входы дают полностью равные результаты, включая IDs. Авторский код остаётся доверенным: обращения к системному времени, случайности и внешним ресурсам не перехватываются. Отдельный исследовательский процесс/IPC и защита live от тяжёлого исследовательского кода ещё впереди; нынешний запуск предназначен для офлайн-работы.

Оптимизация в обычном runtime работает как прежде. В SingleBacktest запуск OPTIMIZING явно запрещён: длительность/момент завершения работы должны быть сначала заданы в модельном времени, чтобы расчёт не зависел от скорости компьютера. Это отдельное продолжение UC28, а не отмена согласованного статуса. Портфельный бэктест UC25 остаётся следующей самостоятельной итерацией.

## Проверки и демонстрация

На локальной проверке прошли **137 тестов**, из них **33 новых**, strict mypy для ядра и пяти демонстраций, а также проверка типов для win32. Поведение проверено через свечи/fills/позиции/P&L, а не сравнением внутреннего устройства классов. Включены повторяемость запуска, защита от будущей истории, синтетический гэп, отдельная коррекция, ошибки фильтра и неизменность часов после отказа, market/limit, cancel/replace, комиссии, short и множитель, открытый цикл и последняя неисполненная заявка.

```sh
python -m unittest discover -s tests_v2 -v
python -m mypy
python examples/v2_backtest.py
```

Демонстрация прогревает один бар и обрабатывает четыре, включая один синтетический. Вход 2 лота по limit 100 ждёт реальную свечу после пустого интервала; выход исполняется по limit 110. Две комиссии по 1 дают P&L **18 RUB**, позиция 0. Повторный запуск возвращает полностью равный результат. Все пять демонстраций проходят локально; CI настроен на Linux и Windows.

## Что остаётся

Реальные тики/стакан, брокерский источник истории, upstream multiplexing, календарь биржи, stale-таймеры и автоматическая загрузка пропусков ещё не реализованы. Нет портфельного запуска, моделируемого расписания оптимизации, отдельного исследовательского процесса, GUI-отчётов и live-подключения. Эти границы отмечены в UC13–15, UC24–28. Следующий основной этап плана — счета и распределение капитала; недостающие расширения market data остаются в реестре.
