# Первая проверка подключения QUIK — только чтение

14 октября 2026 года. Ветка `rewrite/v2-quik-readonly`.

Первое подключение выполняем к **официальному демо QUIK 13.2 x64**. Боевой ПСБ — отдельный контур: **13.0.2.20 x64, Lua 5.4**, по сообщению пользователя. У ПСБ демо-счёта нет; официальный demo не считается эквивалентом настроек, комиссий и маржинальных данных ПСБ. Версия Lua демо пока не подтверждена. Скрипт ниже проверит её до загрузки DLL; этот срез поддерживает Lua 5.4.

## 1. Обновить код и проверить пример

В PowerShell из корня своего репозитория:

```powershell
git fetch origin
git switch rewrite/v2-quik-readonly
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m unittest discover -s tests_v2 -v
.\.venv\Scripts\python.exe examples/v2_quik_readonly.py
```

Ожидаются 453 теста и три сообщения примера. Пример открывает случайные локальные порты для синтетического терминала и к QUIK не обращается. `lupa==2.6` нужна только тестам Lua-защиты; Python-клиент использует стандартную библиотеку и не устанавливает `quik-python`.

## 2. Подготовить отдельную папку Lua bridge

Используем Lua-часть [Alex-Shur/quik_python, commit 0eae024ea43547ab933c705d0951d37e3533d675](https://github.com/Alex-Shur/quik_python/tree/0eae024ea43547ab933c705d0951d37e3533d675). Если reference-копия уже подготовлена в прошлой итерации, повторно клонировать не нужно; проверьте её commit.

```powershell
git clone https://github.com/Alex-Shur/quik_python.git ..\quik-python-reference
git -C ..\quik-python-reference checkout 0eae024ea43547ab933c705d0951d37e3533d675
New-Item -ItemType Directory -Path .\data\quik-demo-bridge
Copy-Item ..\quik-python-reference\lua\* .\data\quik-demo-bridge\ -Recurse
Copy-Item .\quik\TradingSystemReadOnly.lua .\data\quik-demo-bridge\
Copy-Item .\quik\config.readonly.example.json .\data\quik-demo-bridge\config.json
```

Это должна быть новая отдельная папка. Если она уже существует, используйте другое имя или проверьте её содержимое перед копированием. Копия штатного `config.json` заменяется только в этой новой папке. Рабочие журналы OMS/QUIK из предыдущих итераций здесь не используются.

В демо-терминале откройте диалог работы с Lua-скриптами, добавьте и запустите **TradingSystemReadOnly.lua** из этой папки. Сам `QuikSharp.lua` отдельно запускать не нужно: наш скрипт загружает его, устанавливает запрет всех команд вне списка чтения и затем запускает сервер.

Сохраните в конфигурации адреса **127.0.0.1**, порты **34130 / 34131**. До запуска Python скрипт может ждать клиента — это нормально. Эти порты должны принадлежать демо-скрипту. Если другая копия bridge уже использует их, остановите её либо назначьте отдельную пару портов в конфигурации и аргументах команды.

Сначала проверяется `_VERSION == "Lua 5.4"`; при другой версии текст ошибки покажет фактическую Lua, и загрузка bridge не продолжится. В закреплённой версии upstream для современных QUIK выбран `clibs64/54_MT`. Это основание для первоначальной проверки, а не подтверждение ABI вашего терминала. При ошибке загрузки DLL пришлите текст ошибки; не заменяйте DLL случайной другой версией. [Исходная инструкция автора](https://github.com/Alex-Shur/quik_python/blob/0eae024ea43547ab933c705d0951d37e3533d675/lua/USAGE.RU.md) содержит варианты LuaSocket и ссылку Microsoft для runtime Visual C++.

## 3. Запустить диагностическое чтение

Терминал должен быть подключён к демо-серверу. В том же PowerShell:

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile demo-quik --expect-version 13.2 --output .\data\quik-demo-check-01
```

Команда проверит профиль `demo-quik`, версию QUIK с префиксом 13.2, Lua 5.4, режим чтения и связь терминала с сервером. Затем получит список классов и два набора таблиц счетов, заявок, сделок, фьючерсных позиций и лимитов. Названия счетов и их номера в консоль не выводятся.

Для каждого повторного запуска указывайте новый каталог, например `quik-demo-check-02`: старые отчёты не перезаписываются. Код завершения: **0** — получены повторяемые наблюдения; **2** — чтение завершено, но во время него замечены изменения; **1** — ошибка/неполные данные. Любой код оставляет торговлю неразрешённой: диагностический клиент не связан с OMS и не имеет функций отправки заявок.

Ожидаемые строки:

```text
READ_ONLY demo-quik: QUIK <фактическая сборка>; Lua 5.4
Classes: <классы, доступные в демо>
Rows: accounts=..., orders=..., trades=..., holdings=..., limits=...
Repeatable observation: True; reconciled: False
Report: data\quik-demo-check-01\report.json
```

Пришлите эти строки либо короткий текст ошибки. Полный `report.json` и журнал могут содержать номера счетов и сделок; для начальной диагностики они не нужны.

## 4. Проверить выбранный инструмент

Сначала посмотрите реальные классы в результате предыдущей команды. Демо может предоставлять другой набор, поэтому SPBFUT не подставляется автоматически. Выберите класс и точный код инструмента из терминала. К прежней команде добавьте `--class-code ИМЯ_КЛАССА --symbol КОД_ИНСТРУМЕНТА` и новый `--output`.

Получение метаданных проверяет соответствие класса/кода и наличие положительного шага цены/лота. Оно пока не превращает метаданные в торговый Route, не определяет финансовый множитель, не рассчитывает доступный капитал и не загружает стратегию.

## Боевой ПСБ и ограничения

Проверку ПСБ выполняем отдельным запуском после демо. Для него нужна отдельная папка bridge, метка `local PROFILE = "psb-live"` в копии TradingSystemReadOnly.lua и своя пара портов, например 34132/34133. Команда получает `--profile psb-live --expect-version 13.0.2.20 --request-port 34132 --callback-port 34133` и отдельный новый каталог отчёта. Метка профиля задаётся в локальном скрипте; это защита от перепутанной конфигурации, а не удостоверение брокера.

Два одинаковых чтения не образуют атомарный снимок брокера. Пустая таблица означает только пустую видимую таблицу терминала; не доказано, что все данные и права загружены. Независимая сверка с ledger, граница callbacks, включение исполнения, нативные стопы и возобновление торговли остаются следующими историями. Этот инструмент ничего не импортирует в ручную стратегию и не снимает блокировки OMS.
