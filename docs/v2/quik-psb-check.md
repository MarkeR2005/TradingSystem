## Что показал первый отчёт

По сообщению пользователя запуск выполнен через терминал ПСБ; отчёт от 17 октября, 15:41 МСК содержит QUIK 13.0.2.20 / Lua 5.4 и инструмент SPBFUT/SRZ6 (SBRF-12.26). Ограничение выходного дня учебного сервера из инструкции демо не переносится на этот терминал.

| Наблюдение | Причина и действие |
| --- | --- |
| `accounts.invalid_identity` | Один фондовый `trdaccid` содержит `+`. Наш валидатор ошибочно применял к наблюдаемым счетам ограничения идентификатора торгового маршрута. Исправлено в Python; символ сохраняется в точном ключе, ограничения отправки заявок не расширены. |
| `BUYDEPO.nonpositive_value` | В обоих ответах API: result="1", type="2", value="0.000000", пустое отображение. SELLDEPO=5461.57, шаг цены и стоимость шага=1 SUR. Причина нулевого BUYDEPO по отчёту не установлена; он не заменяется SELLDEPO и не трактуется как разрешённое нулевое ГО. |
| `profile=demo-quik` при запуске ПСБ | В локальной копии Lua осталась демо-метка. Профиль задаётся вручную, он не определяет брокера по соединению. Нужно настроить отдельную копию как `psb-live`. Старые отчёты не переименовывать и не исправлять задним числом. |

Справочник SRZ6: lot_size=100, qty_multiplier=1, qty_scale=0, шаг цены 1. Размер лота не подставляется вместо денежного множителя. Реквизиты и балансы счетов в этот документ и тесты не перенесены.

После исправления сохранённые ответы проверены локально через чистый анализатор и TCP-стенд: три строки лимитов полны; режим только `--limits` завершает диагностику с кодом 0. Совместный режим сохраняет код 2 из-за исходного BUYDEPO=0; лимиты имеют `complete=True`, но `repeatable_observation=False` с `snapshot_unverified`. Убрано повторное отражение этой же финансовой ошибки обратно как `snapshot_unstable`. Это воспроизведение приложенных ответов, не новый запуск на терминале.

## Разделить конфигурации терминалов

Для ПСБ используйте отдельную папку bridge с уже закреплённой Lua-частью upstream и `TradingSystemReadOnly.lua`; демо-папку оставьте отдельной. Если ПСБ сейчас использует ту же папку, сначала остановите его read-only скрипт и подготовьте отдельную копию. Порядок первоначальной подготовки файлов описан в [инструкции подключения](quik-readonly-check.md).

В **копии для ПСБ** измените начало `TradingSystemReadOnly.lua`:

```lua
local PROFILE = "psb-live"
```

Сохраните рабочие порты из соседнего `config.json`, из записи с `scriptName: "TradingSystemReadOnly"`. В подтверждённом запуске пользователя это **34130/34131**; оба адреса — `127.0.0.1`. Смена профиля на psb-live не требует смены портов. Если одновременно запущены два bridge на одном компьютере, им нужны разные свободные пары: например, второму можно назначить 34132/34133, изменив и config.json, и аргументы Python. Для последовательных запусков подходит одна и та же пара.

Перезапустите `TradingSystemReadOnly.lua` после изменения его PROFILE или конфигурации. Сам `QuikSharp.lua` отдельно не запускайте. Прежняя инструкция без необходимости меняла команду на 34132/34133; при работающем bridge на 34130/34131 это привело к отказу подключения. Рабочую пару пользователя сохраняем.

Ожидаемая строка нового отчёта: `READ_ONLY psb-live: QUIK 13.0.2.20; Lua 5.4`. Проверка профиля сравнивает две настройки пользователя; это не автоматическое удостоверение брокера или типа счёта. Режим остаётся только читающим.

При прежних полных стабильных данных ожидаются `complete=True`, `repeatable=True`, `requested=False`, `verified=False`. Выбор строки ещё не запрашивается; капитал и торговый допуск не создаются. Сравните значения отчёта с таблицей «Ограничения по клиентским счетам» в ПСБ, используя локальную расшифровку ключей. Для обратной связи достаточно консоли и `limits.json`; суммы в нём сохраняются. Полный `report.json` и файл ключей содержат реквизиты — оставьте их локально.

## Отказ проверки подключения — 18 октября

Пользователь сообщил отображаемые ГО: покупателя 5292.77, продавца 5461.57. Это отдельное наблюдение; оно не заменяет значения API из более раннего снимка. Следующая попытка с ожидаемыми `psb-live` / `13.0.2.20` остановилась до чтения финансовых параметров:

```text
connection handshake failed: read-only protocol, profile, Lua or QUIK version mismatch
```

Такой текст означает, что получен ответ на `tsRuntimeInfo`, но не прошла проверка его формы, протокола, режима, профиля или версий. Конкретное несовпадение старое сообщение не сохраняет. Нельзя по нему утверждать, что запущен демо-профиль, изменена версия QUIK или причина связана с ГО.

Исправление Python перечисляет несовпавшие поля с `expected` и `observed`; для QUIK используется `expected_prefix` с прежним сравнением числовых компонентов. Пропущенные поля обозначаются `<missing>`. Строки ограничены 80 символами, управляющие символы экранированы, вложенные объекты заменены названием типа. Посторонние поля ответа не включаются. При несовпадении соединение по-прежнему закрывается до ping и чтения таблиц, а runtime не становится подтверждённым.

Для уже сохранённого неудачного запуска обновление и повторное подключение не нужны. Из корня репозитория в PowerShell выполните следующую команду; если каталог запуска отличался, замените только путь `path`:

```powershell
@'
import base64, json
from pathlib import Path

path = Path("data/quik-psb-financial-02/wire/events.jsonl")
fields = ("protocol", "mode", "profile", "lua_version", "quik_version")
with path.open(encoding="utf-8") as log:
    for line in log:
        event = json.loads(line)["payload"]
        if event.get("event") != "response":
            continue
        frame = json.loads(base64.b64decode(event["bytes_b64"]).decode("cp1251"))
        if frame.get("cmd") == "tsRuntimeInfo":
            info = frame["data"]
            if isinstance(info, dict):
                print(json.dumps({key: info.get(key) for key in fields}, indent=2))
            else:
                print("Unexpected tsRuntimeInfo data type:", type(info).__name__)
            break
    else:
        print("No tsRuntimeInfo response found in this journal")
'@ | .\.venv\Scripts\python.exe -
```

Команда только читает файл и выводит пять полей; сокеты не открываются, журнал не изменяется. Пришлите её вывод, полный wire-журнал со счетами не требуется. После этого можно адресно исправить конфигурацию. Рабочие порты **34130/34131** сохраняются. Не подставляйте наблюдённый профиль или версию в аргументы только ради прохождения проверки: сначала сверьте запущенную Lua-копию и терминал.
