## Разделить конфигурации терминалов

Для ПСБ используйте отдельную папку bridge с уже закреплённой Lua-частью upstream и `TradingSystemReadOnly.lua`; демо-папку оставьте отдельной. Если ПСБ сейчас использует ту же папку, сначала остановите его read-only скрипт и подготовьте отдельную копию. Порядок первоначальной подготовки файлов описан в [инструкции подключения](quik-readonly-check.md).

Локальный профиль хранится рядом с запускаемой обёрткой в отдельном файле **`TradingSystemReadOnly.profile.local`**. Его содержимое — одна строка `psb-live`, без кавычек. Файл исключён из Git; исходный Lua больше не нужно редактировать. Для демо в своей папке используйте `demo-quik`; шаблон находится в `quik/TradingSystemReadOnly.profile.example`.

Перед первым переходом остановите read-only скрипт. В примере ниже замените `$quikPsbBridge` на фактическую папку скрипта, выбранного в диалоге QUIK. Проверка пути защищает от создания настройки в случайной папке:

```powershell
$quikPsbBridge = '.\data\quik-psb-bridge'
if (-not (Test-Path -LiteralPath "$quikPsbBridge\TradingSystemReadOnly.lua" -PathType Leaf)) {
    throw 'Укажите фактическую папку Lua bridge ПСБ'
}
Set-Content -LiteralPath "$quikPsbBridge\TradingSystemReadOnly.profile.local" -Value 'psb-live' -Encoding ascii
Copy-Item -LiteralPath .\quik\TradingSystemReadOnly.lua -Destination $quikPsbBridge
```

При последующих обновлениях копируйте только Lua-обёртку; локальный файл профиля и рабочий `config.json` сохраняются. Поддерживаются ASCII/UTF-8, необязательный BOM, окончание строки LF/CRLF. Профиль — 1–64 символа `A–Z`, `a–z`, `0–9`, `_`, `.`, `:`, `-`; содержимое не исполняется как Lua. Пустой, повреждённый или недоступный файл останавливает запуск до загрузки bridge. Если файла вообще нет, для совместимости остаётся старый профиль из Lua (в исходной копии `demo-quik`); Python по-прежнему проверяет совпадение с `--profile`.

Сохраните рабочие порты из соседнего `config.json`, из записи с `scriptName: "TradingSystemReadOnly"`. В подтверждённом запуске пользователя это **34130/34131**; оба адреса — `127.0.0.1`. Смена профиля на psb-live не требует смены портов. Если одновременно запущены два bridge на одном компьютере, им нужны разные свободные пары: например, второму можно назначить 34132/34133, изменив и config.json, и аргументы Python. Для последовательных запусков подходит одна и та же пара.

Перезапустите `TradingSystemReadOnly.lua` после изменения локального файла профиля или конфигурации. Сам `QuikSharp.lua` отдельно не запускайте. Прежняя инструкция без необходимости меняла команду на 34132/34133; при работающем bridge на 34130/34131 это привело к отказу подключения. Рабочую пару пользователя сохраняем.

Ожидаемая строка нового отчёта: `READ_ONLY psb-live: QUIK 13.0.2.20; Lua 5.4`. Проверка профиля сравнивает две настройки пользователя; это не автоматическое удостоверение брокера или типа счёта. Режим остаётся только читающим.

## Отказ проверки подключения — 18 октября

Пользователь сообщил отображаемые ГО: покупателя 5292.77, продавца 5461.57. Это отдельное наблюдение; оно не заменяет значения API из более раннего снимка. Следующая попытка с ожидаемыми `psb-live` / `13.0.2.20` остановилась до чтения финансовых параметров:

```text
connection handshake failed: read-only protocol, profile, Lua or QUIK version mismatch
```

Такой текст означает, что получен ответ на `tsRuntimeInfo`, но не прошла проверка его формы, протокола, режима, профиля или версий. Конкретное несовпадение старое сообщение не сохраняет. Нельзя по нему утверждать, что запущен демо-профиль, изменена версия QUIK или причина связана с ГО.

Исправление Python перечисляет несовпавшие поля с `expected` и `observed`; для QUIK используется `expected_prefix` с прежним сравнением числовых компонентов. Пропущенные поля обозначаются `<missing>`. Строки ограничены 80 символами, управляющие символы экранированы, вложенные объекты заменены названием типа. Посторонние поля ответа не включаются. При несовпадении соединение по-прежнему закрывается до ping и чтения таблиц, а runtime не становится подтверждённым.

Причина этого случая уже подтверждена пользователем: локальное изменение PROFILE было отменено при обновлении Lua из GitHub. После восстановления psb-live чтение прошло; извлекать старый ответ больше не требуется. Следующая команда остаётся справочной для аналогичного отказа в будущем: она читает существующий журнал без подключения. При необходимости замените путь `path` на каталог нужного запуска:

```powershell
@'
import base64, json
from pathlib import Path

path = Path("data/quik-psb-financial-02/wire/events.jsonl")
fields = ("protocol", "mode", "profile", "lua_version", "quik_version")
with path.open(encoding="utf-8") as log:
    for line in log:
        event = json.loads(line)["payload"]
        if event.get("event") != "response":
            continue
        frame = json.loads(base64.b64decode(event["bytes_b64"]).decode("cp1251"))
        if frame.get("cmd") == "tsRuntimeInfo":
            info = frame["data"]
            if isinstance(info, dict):
                print(json.dumps({key: info.get(key) for key in fields}, indent=2))
            else:
                print("Unexpected tsRuntimeInfo data type:", type(info).__name__)
            break
    else:
        print("No tsRuntimeInfo response found in this journal")
'@ | .\.venv\Scripts\python.exe -
```

Команда только читает файл и выводит пять полей; сокеты не открываются, журнал не изменяется. Для разбора аналогичного отказа достаточно этого вывода, полный wire-журнал со счетами не требуется. Рабочие порты **34130/34131** сохраняются. Не подставляйте наблюдённый профиль или версию в аргументы только ради прохождения проверки: сначала сверьте запущенную Lua-копию и терминал.
