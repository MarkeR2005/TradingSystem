# Проверка лимитов ПСБ — только чтение

17 октября 2026 года. Ветка `rewrite/v2-quik-limits`, исправление в итерации 18.

## Что показал первый отчёт

По сообщению пользователя запуск выполнен через терминал ПСБ; отчёт от 17 октября, 15:41 МСК содержит QUIK 13.0.2.20 / Lua 5.4 и инструмент SPBFUT/SRZ6 (SBRF-12.26). Получены три счёта и три строки фьючерсных лимитов типов 0/6/7; заявок, сделок и позиций нет. Два чтения совпадают, callbacks нет. Ограничение выходного дня учебного сервера из инструкции демо не переносится на этот терминал.

| Наблюдение | Причина и действие |
| --- | --- |
| `accounts.invalid_identity` | Один фондовый `trdaccid` содержит `+`. Наш валидатор ошибочно применял к наблюдаемым счетам ограничения идентификатора торгового маршрута. Исправлено в Python; символ сохраняется в точном ключе, ограничения отправки заявок не расширены. |
| `BUYDEPO.nonpositive_value` | В обоих ответах API: result="1", type="2", value="0.000000", пустое отображение. SELLDEPO=5461.57, шаг цены и стоимость шага=1 SUR. Причина нулевого BUYDEPO по отчёту не установлена; он не заменяется SELLDEPO и не трактуется как разрешённое нулевое ГО. |
| `profile=demo-quik` при запуске ПСБ | В локальной копии Lua осталась демо-метка. Профиль задаётся вручную, он не определяет брокера по соединению. Нужно настроить отдельную копию как `psb-live`. Старые отчёты не переименовывать и не исправлять задним числом. |

Справочник SRZ6: lot_size=100, qty_multiplier=1, qty_scale=0, шаг цены 1. Размер лота не подставляется вместо денежного множителя. Реквизиты и балансы счетов в этот документ и тесты не перенесены.

После исправления сохранённые ответы проверены локально через чистый анализатор и TCP-стенд: три строки лимитов полны; режим только `--limits` завершает диагностику с кодом 0. Совместный режим сохраняет код 2 из-за исходного BUYDEPO=0; лимиты имеют `complete=True`, но `repeatable_observation=False` с `snapshot_unverified`. Убрано повторное отражение этой же финансовой ошибки обратно как `snapshot_unstable`. Это воспроизведение приложенных ответов, не новый запуск на терминале.

Ожидаются **526 тестов**. Исправление `+` не требует новой версии Lua-обёртки. Изменение её локального PROFILE ниже нужно для правильной маркировки ПСБ.

## Разделить конфигурации терминалов

Для ПСБ используйте отдельную папку bridge с уже закреплённой Lua-частью upstream и `TradingSystemReadOnly.lua`; демо-папку оставьте отдельной. Если ПСБ сейчас использует ту же папку, сначала остановите его read-only скрипт и подготовьте отдельную копию. Порядок первоначальной подготовки файлов описан в [инструкции подключения](quik-readonly-check.md).

В **копии для ПСБ** измените начало `TradingSystemReadOnly.lua`:

```lua
local PROFILE = "psb-live"
```

В соседнем `config.json`, в записи с `scriptName: "TradingSystemReadOnly"`, установите `responsePort: 34132`, `callbackPort: 34133`. Оба адреса оставьте `127.0.0.1`. Эта пара должна быть свободна; если уже занята, выберите другую и передайте её же Python-клиенту. У демо остаются собственные метка и порты. Перезапустите `TradingSystemReadOnly.lua` в терминале ПСБ после изменения конфигурации. Сам `QuikSharp.lua` отдельно не запускайте.

Ожидаемая строка нового отчёта: `READ_ONLY psb-live: QUIK 13.0.2.20; Lua 5.4`. Проверка профиля сравнивает две настройки пользователя; это не автоматическое удостоверение брокера или типа счёта. Режим остаётся только читающим.

## Сначала проверить лимиты независимо от ГО инструмента

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile psb-live --expect-version 13.0.2.20 --request-port 34132 --callback-port 34133 --limits --output .\data\quik-psb-limits-01
```

При прежних полных стабильных данных ожидаются `complete=True`, `repeatable=True`, `requested=False`, `verified=False`. Выбор строки ещё не запрашивается; капитал и торговый допуск не создаются. Сравните значения отчёта с таблицей «Ограничения по клиентским счетам» в ПСБ, используя локальную расшифровку ключей. Для обратной связи достаточно консоли и `limits.json`; суммы в нём сохраняются. Полный `report.json` и файл ключей содержат реквизиты — оставьте их локально.

## Отдельно уточнить BUYDEPO

В Таблице текущих торгов для **SPBFUT/SRZ6** сравните отображаемые ГО покупателя и продавца с результатом API. Если ГО покупателя тоже отсутствует/нулевое, источник пока не даёт положительного значения для нашего диагностического кандидата. Если в таблице положительная сумма, зафиксируйте это расхождение и повторите чтение в новом каталоге:

```powershell
.\.venv\Scripts\python.exe -m trading_system.quik_probe --profile psb-live --expect-version 13.0.2.20 --request-port 34132 --callback-port 34133 --class-code SPBFUT --symbol SRZ6 --financial --limits --output .\data\quik-psb-financial-01
```

При неизменном BUYDEPO=0 ожидается код 2: `BUYDEPO.nonpositive_value` у инструмента и `snapshot_unverified` у лимитов. `accounts.invalid_identity` для наблюдённого счёта с `+` после исправления отсутствует. Для разбора ГО достаточно `instrument.json` и значений соответствующих полей на экране; реальная отправка заявок этой проверкой не предусмотрена.
